# 🌲 Тополь — Table Sync Engine

Автоматический пинг-понг статусов между 4 таблицами Google Sheets по 9 шагам цепочки движения видео-контента.

## 🎯 Что делает

Автоматизирует конвейер производства видео:
- Сценарий → клиент → сценарист → менеджер → монтажёр → клиент
- Проверяет статусы каждые 5 минут
- Сохраняет историю в PostgreSQL
- Показывает состояние через Web UI

## ⚡ 9 шагов цепочки

1. **Сценарий одобрен** → копирование в клиентскую таблицу
2. **Пинг-понг сценарист ↔ клиент** — синхронизация правок
3. **Дедлайн + исходник + готово** → уведомление менеджеру
4. **Пинг-понг менеджер ↔ сценарист** — одобрение исходника
5. **Выбор монтажёра** → задание в таблицу монтажёра
6. **Пинг-понг монтажёр ↔ менеджер** — статус монтажа
7. **Монтаж одобрен** → отправка клиенту
8. **Клиент одобрил** → ссылка сценаристу
9. **Сценарист: дата + описание** → финальное обновление

## 🛡 Безопасность (после инцидента Step 0)

Движок пишет в живые продакшн-таблицы, поэтому встроены предохранители:

| Переменная | По умолчанию | Что делает |
|------------|--------------|------------|
| `TOPOL_DRY_RUN` | `1` (вкл) | Все записи только логируются (`[DRY-RUN] would write…`), реально в таблицы ничего не уходит. Для боевого режима — `TOPOL_DRY_RUN=0`. |
| `TOPOL_MAX_WRITES` | `50` | Потолок записей за один цикл. При превышении срабатывает **circuit breaker** — цикл прерывается (`CircuitBreakerTripped`), чтобы массовый сбой не разлился по таблицам. |
| `TOPOL_SCAN_ROWS` | `30` | Сколько последних строк сканировать в каждом табе. Узкое окно = быстрый цикл, и **старые строки выше окна не читаются и не трогаются** — движок работает только по свежим и активным строкам (внизу таблицы). Если активная работа идёт по более старым строкам — увеличьте значение. |
| `TOPOL_INTERVAL_MINUTES` | `10` | Период главного цикла синхронизации. |
| `TOPOL_BACKFILL_MINUTES` | `60` | Период фоновой задачи до-наполнения (см. ниже). |
| `TOPOL_BACKFILL_MAX` | `200` | Максимум строк, которые backfill добавляет за один прогон. |

### ⏳ Backfill — до-наполнение недостающих строк (раз в час)

Главный цикл быстрый и смотрит только последние `TOPOL_SCAN_ROWS` строк. Отдельная
фоновая задача (`backfill.py`, по умолчанию раз в час) проходит по клиентским табам
целиком и добавляет в СценарииСбор строки, которых там нет (дедуп по ID, мэппинг
колонок **по имени**).

Ключевая защита от повтора инцидента: добавленные строки **сразу помечаются как
обработанные** для шагов, стартующих из СценарииСбор (включая Step 5
`assign_to_montager`). Поэтому импорт НЕ вызывает рассылку монтажёрам — движок
среагирует только на *будущие реальные изменения* этих строк. Backfill уважает
`TOPOL_DRY_RUN` и имеет потолок `TOPOL_BACKFILL_MAX` на прогон.

```bash
docker exec topol-engine python3 /app/backfill.py   # разовый прогон (с учётом DRY_RUN)
```

Дополнительно: `assign_to_montager` идемпотентен — не дублирует задание, если ID
уже есть в таблице монтажёра (защита, даже если PostgreSQL-дедуп недоступен).

### Восстановление после инцидента

```bash
# 1. Отчёт: какие строки у монтажёров — мусор (НЕ удаляет)
docker exec topol-engine python3 /app/cleanup_montagers.py
# 2. Удалить (после проверки отчёта)
docker exec topol-engine python3 /app/cleanup_montagers.py --apply --yes

# 3. Отчёт: что вернётся в СценарииСбор (НЕ пишет)
docker exec topol-engine python3 /app/restore_scenariisbor.py
# 4. Записать (мэппинг колонок ПО ИМЕНИ, не по позиции)
docker exec topol-engine python3 /app/restore_scenariisbor.py --apply --yes
```

### ⚠️ Главное правило

**Никогда не добавляйте Step, который массово создаёт строки и сразу отдаёт их
следующим шагам.** Импорт — только разовым скриптом вне движка (как
`restore_scenariisbor.py`), с мэппингом колонок по имени и без авто-назначения.
